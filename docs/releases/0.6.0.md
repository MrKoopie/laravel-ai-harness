# Laravel AI Harness 0.6.0

> [!WARNING]
> **BREAKING CONFIGURATION CHANGES — rename the removed keys before upgrading.**
> All seven keys below are rejected in 0.6.0; there are no compatibility aliases or automatic migration. Composer's refresh hook and harness commands fail if any remain, including in personal files inherited by worktrees.

| Removed key | Replacement |
| --- | --- |
| `herd_php` | `php_version` |
| `valet_php` | `php_version` |
| `yerd_php` | `php_version` |
| `herd_secure` | `site_secure` |
| `valet_secure` | `site_secure` |
| `yerd_secure` | `site_secure` |
| `services` | `service_manager` |

Keep the existing values. If a file has settings for several runtimes, keep one `php_version` and one `site_secure` for the selected runtime and remove every old key. Keep `sail_services` unchanged: it still lists Sail services. Cloud settings and resource ownership state are unchanged.

## Upgrade instructions

1. **Before running Composer**, rename the keys in every existing `.ai-harness.config.dist`, `.ai-harness.config`, `.ai-harness.config.global`, and `.ai-harness.config.local`. Include the primary checkout's inherited personal files and each worktree's overrides.
2. Use host Composer for this transition. A `^0.5` constraint does **not** include 0.6.0. For a project installation, run:

   ```bash
   composer require --dev 'mrkoopie/laravel-ai-harness:^0.6'
   ./.ai-harness update
   ./.ai-harness doctor
   ./.ai-harness setup
   ```

3. Commit shared configuration changes, Composer files, and refreshed managed files. Each collaborator must migrate their personal files too. Refresh existing linked worktrees with `update`, `doctor`, and `setup`.

For an existing global installation, use `composer global require 'mrkoopie/laravel-ai-harness:^0.6'`, then run `ai-harness update`, `ai-harness doctor`, and `ai-harness setup` in each configured project and existing worktree.

**Already hit a failed update hook?** Use `composer require --dev 'mrkoopie/laravel-ai-harness:^0.6' --no-scripts` (or `composer global require 'mrkoopie/laravel-ai-harness:^0.6' --no-scripts` for a global installation), rename all removed keys, then run `update`, `doctor`, and `setup`. Review and run any unrelated Composer scripts skipped by `--no-scripts` separately.

Read the [complete 0.6.0 upgrade guide](https://github.com/MrKoopie/laravel-ai-harness/blob/v0.6.0/docs/upgrading.md#upgrade-to-060) for examples, inheritance details, and recovery steps.

## Changes since 0.5.1

- **Global Composer installation:** install once with `composer global require mrkoopie/laravel-ai-harness`, then run `ai-harness init --global` in each project. Personal configuration uses `.ai-harness.config.global`. Claude uses `settings.local.json` and `CLAUDE.local.md`; Codex uses `AGENTS.override.md` and a local environment. Generated integrations are excluded through `.git/info/exclude`, keeping the shared `.gitignore` unchanged. Linked worktrees inherit configuration, including nested applications. Existing Claude settings retain their file permissions. [#28](https://github.com/MrKoopie/laravel-ai-harness/pull/28)
- **Shared runtime configuration:** `php_version`, `site_secure`, and `service_manager` replace the keys above. Site preferences follow the selected Herd, Valet, or Yerd runtime. Empty `php_version` preserves an existing selection; native PHP, Sail, and cloud execution ignore the site preferences. **Herd now writes HTTP URLs when HTTPS is disabled.** [#27](https://github.com/MrKoopie/laravel-ai-harness/pull/27)
- **Yerd 2.x support:** first-class runtime commands, site setup, PHP selection, HTTPS, worktree hooks, health checks, and cleanup of harness-owned sites. [#26](https://github.com/MrKoopie/laravel-ai-harness/pull/26)
- **Personal environment overrides:** configure `local_env.*` settings without committing machine-specific values. Linked local worktrees inherit the primary checkout's personal defaults; setup validates conflicts and applies the overrides. [#25](https://github.com/MrKoopie/laravel-ai-harness/pull/25)

## Validation

The release code passed all 325 local tests (1,455 assertions) and CI on PHP 8.2–8.5, including formatting, Composer validation, ShellCheck, and static analysis. The release documentation was checked against all seven removed-key regression tests.
