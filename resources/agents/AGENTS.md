# AI Harness

- Run Laravel commands through `./.ai-harness artisan ...`.
- Run tests through `./.ai-harness test ...`.
- Run Composer, PHP, and npm through `./.ai-harness composer ...`, `./.ai-harness php ...`, and `./.ai-harness npm ...`.
- In Codex, when planning to execute a command that invokes Laravel Herd, Laravel Valet, or Yerd, run that command outside the sandbox on the first attempt (`sandbox_permissions=require_escalated`). This applies to direct `herd ...`, `ai-herd ...`, `valet ...`, and `yerd ...` commands, and to `./.ai-harness ...` commands that will invoke Herd, Valet, or Yerd under the active runtime. Request escalation only for the planned command, not merely because Herd, Valet, or Yerd is configured.
- Use `./.ai-harness up`, `./.ai-harness down`, and `./.ai-harness doctor` for the configured local environment.
- Put personal application overrides in `.ai-harness.config.local` as `local_env.VARIABLE=value`, then run `./.ai-harness setup`. Linked local worktrees inherit the primary checkout's local file before their own; use `doctor` to inspect sources without revealing values. Use `local_env.FORWARD_DB_PORT` for managed Sail MySQL. Preserve generated database names, site URLs, and isolated testing defaults; do not copy an entire primary `.env`. Cloud execution ignores local environment overrides.
- Preserve all environment-provided `AI_HARNESS_*` configuration values for every later harness command, including PHP, Artisan, Composer, tests, doctor, and cleanup. This includes `AI_HARNESS_RUNTIME`, `AI_HARNESS_PHP_VERSION`, `AI_HARNESS_SITE_SECURE`, `AI_HARNESS_SAIL_SERVICES`, database choices, agents/worktrees, Sail/cloud services and switches, and the JSON `AI_HARNESS_LOCAL_ENV` map. Re-export the same values when a fresh shell does not inherit them; do not evaluate local override values as shell code. Use `doctor` to inspect sources without exposing credentials. Setup-only exports do not configure future commands. Do not copy exported overrides into harness config files or Laravel `.env`; setup applies explicit local application overrides and generated values normally.
- Do not bypass the configured runtime unless the user explicitly asks.
- Cloud detection uses `CLAUDE_CODE_REMOTE=true` or explicit `AI_HARNESS_ENV=claude-cloud|codex-cloud`; `local` overrides detection. Cloud commands use native PHP and local services.
- In cloud sessions, run `./.ai-harness cloud maintain` after restoring a cached checkout. Use `./.ai-harness cloud cleanup` to remove only owned testing databases; development data is preserved.
- In Claude cloud sessions, SessionStart prepares ordinary clones and resumed sessions. SessionEnd removes only owned testing databases and preserves development data. Multi-repository sessions need explicit `./.ai-harness cloud setup` per project because repository hooks are not loaded.
